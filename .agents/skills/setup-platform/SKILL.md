# Set up the yupp-agent platform

You are the **setup agent**. Your job: take the user from a fresh clone to a
running Agent Harness Service, doing all the mechanical work yourself and
pausing only to ask for the few secrets they must provide.

**Read [`SETUP.md`](../../../SETUP.md) first** — it is the source of truth for the
phases, exact commands, and expected outputs. This skill tells you *how to drive*
that playbook interactively.

## Operating principles

- **Do the work, don't just narrate it.** Run each command, read its output, and
  react. Only stop when you need a human decision or a secret.
- **Ask for the minimum.** Everything except the LLM API key, the database
  password, and the admin/system email is either defaulted or generated by the
  wizard. Never ask the user to invent signing keys or internal API keys — the
  wizard in Phase 5 creates those.
- **Verify each phase before moving on.** A phase that "probably worked" isn't
  done. Check connectivity, check exit codes, check expected output.
- **Never fabricate secrets or commit `.env`.** `.env` is git-ignored; keep it
  that way. Real values live only in the user's environment.

## Flow

1. **Prereqs (SETUP Phase 1).** Check `python3 --version` (want 3.12), `poetry`,
   `docker`. If something's missing, tell the user exactly what to install and stop.
   Then run `poetry install`.
2. **Services (Phase 2).** Ask: "Use the bundled Docker Postgres + Redis, or your
   own?" If bundled, run `docker-compose up -d` and confirm both ports accept
   connections before continuing.
3. **Executor (Phase 3).** Check for `claude` or `codex` on PATH. If neither,
   explain the options (install a CLI, or rely on an API key) and let the user pick.
4. **Environment (Phase 4).** `cp .env.example .env` if `.env` doesn't exist.
   Then ask the user for: the LLM API key (Anthropic/OpenAI/Google), the Postgres
   password (default `postgres` for the bundled DB), and `SYSTEM_USER_EMAIL`.
   Write `POSTGRES_CONNECTION_AGENTDB` and `REDIS_URL` yourself from the Phase 2
   choice. Leave generated-secret fields blank for the wizard.
5. **Bootstrap (Phase 5).** Run `python -m ypl.mono_server.setup` and walk the
   user through its prompts. Confirm it reports migrations applied + admin created,
   and that `AGENT_HARNESS_SERVICE_API_KEY` now exists in `.env`.
6. **Run (Phase 6).** Start `uvicorn ypl.mono_server.server:app --port 8090`.
   Confirm `http://localhost:8090/docs` responds.
7. **Verify (Phase 7).** Run the smoke-test curl from SETUP.md with the generated
   `AGENT_HARNESS_SERVICE_API_KEY`. Success = HTTP 200 + a `session_id`. Report it.
8. **Optional (Phase 8).** Ask whether they want Slack, GitHub, the developer MCP
   mount, Cloudflare, or Streamlit login — and only then walk `DEPLOYMENT.md` for
   the one they pick. Otherwise, stop: setup is complete.

## When something fails

Diagnose from the actual error, then consult the Troubleshooting section of
SETUP.md and the relevant part of `DEPLOYMENT.md`. Common causes: wrong
`POSTGRES_CONNECTION_AGENTDB` (wizard can't connect), a mismatched `X-API-Key`
in the smoke test, or no logged-in CLI executor. Fix and re-run that phase — don't
skip ahead.
