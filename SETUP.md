# Setting up yupp-agent

This is an **agent-friendly setup playbook**. A human can follow it top to bottom,
and a coding agent (Claude Code, Cursor, etc.) can execute it step by step —
running commands, and pausing to ask you only for the handful of values that
can't be derived automatically (API keys, database credentials).

> **Using an agent?** Open this repo in Claude Code and run `/setup-platform`, or
> just say: *"Follow SETUP.md to set up this platform."* The agent will work
> through the phases below and prompt you when it needs a secret.

The goal: a running Agent Harness Service (AHS) you can talk to, backed by
Postgres + Redis, with at least one working agent executor.

---

## What you need to bring

Only these can't be auto-generated — have them ready:

| Thing | Why | Notes |
|-------|-----|-------|
| An **LLM API key** | Agents call a model | Anthropic **or** OpenAI **or** Google — any one is enough |
| **Claude Code** or **Codex CLI** | The default executors run agents via a CLI | Install + log in; or use an API key |
| A **Postgres 16** database | Persistence | `docker-compose up -d` provides one locally |
| A **Redis 7** instance | Queues / caching | `docker-compose up -d` provides one locally |

Everything else (signing keys, Fernet encryption keys, API keys between the
internal services) is **generated for you** by the setup wizard in Phase 5.

Optional, only if you want them: a Slack app (Slack agents), a GitHub App
(PR review / push), a Cloudflare tunnel (public exposure), a Google OAuth client
(the Streamlit dashboards' login). See [`DEPLOYMENT.md`](./DEPLOYMENT.md).

---

## Phase 1 — Prerequisites

Check you have Python 3.12, Poetry, and Docker (for local Postgres/Redis):

```bash
python3 --version   # expect 3.12.x
poetry --version
docker --version
```

Install dependencies:

```bash
poetry install
```

## Phase 2 — Start Postgres + Redis

The simplest path uses the bundled compose file (Postgres with pgvector, Redis):

```bash
docker-compose up -d
```

This creates a Postgres database named `yadb` and a Redis on `localhost:6379`.
Bringing your own managed Postgres/Redis instead? Skip this and use their
connection details in Phase 4.

## Phase 3 — Install a CLI executor

Agents run through the [Claude Code](https://docs.anthropic.com/en/docs/claude-code)
or [Codex CLI](https://github.com/openai/codex). Install at least one and log in:

```bash
claude --version   # or: codex --version
```

(You can also authenticate the executor purely via an API key set in Phase 4.)

## Phase 4 — Configure the environment

```bash
cp .env.example .env
```

Open `.env` and fill in the **required** values. The rest have working defaults
or are generated by the wizard in Phase 5 — leave them as-is:

- **`ANTHROPIC_API_KEY`** (or `OPENAI_API_KEY` / `GOOGLE_API_KEY`) — at least one.
- **`POSTGRES_CONNECTION_AGENTDB`** — a JSON blob describing the DB connection.
  For the bundled compose Postgres this is:
  ```
  POSTGRES_CONNECTION_AGENTDB={"user":"postgres","password":"postgres","host":"127.0.0.1:5432","database":"yadb"}
  ```
- **`REDIS_URL`** — e.g. `redis://localhost:6379/0`.
- **`SYSTEM_USER_EMAIL`** — the email for the built-in system user (used for
  agent-initiated actions). Any address you control.

> Agent note: prompt the user for the LLM key and the Postgres password. Derive
> host/db from Phase 2 defaults unless the user brought their own database.

## Phase 5 — Bootstrap (migrations + seed + admin)

Run the setup wizard. It checks Postgres/Redis connectivity, runs Alembic
migrations, seeds roles (ADMIN, ENGINEER, MCP_USER), creates your first admin
user, and **auto-generates the internal secrets** (`SECRET_KEY`, Fernet keys,
`X_API_KEY`, `AGENT_HARNESS_SERVICE_API_KEY`) back into `.env`:

```bash
python -m ypl.mono_server.setup
```

Follow the prompts (admin email, etc.). When it finishes, `.env` contains a
generated `AGENT_HARNESS_SERVICE_API_KEY` — you'll need it in Phase 7.

## Phase 6 — Run the platform

```bash
uvicorn ypl.mono_server.server:app --port 8090 --reload
```

Open http://localhost:8090/docs for the OpenAPI page.

The Streamlit dashboards run separately (optional):

```bash
streamlit run ypl/streamlit_server/app.py   # http://localhost:8501
```

## Phase 7 — Verify

Create a test session against the built-in `default` agent. Replace
`<api-key>` with `AGENT_HARNESS_SERVICE_API_KEY` from `.env`:

```bash
curl -s -X POST http://localhost:8090/ahs/sessions \
    -H "Content-Type: application/json" \
    -H "X-API-Key: <api-key>" \
    -d '{
        "agent_name": "default",
        "user_message": "Hello, what tools do you have?",
        "max_turns": 3
    }' | python3 -m json.tool
```

Expected: HTTP 200 with a `session_id`. 🎉 The platform is up.

## Phase 8 — Optional integrations

All off by default; enable only what you need (see [`DEPLOYMENT.md`](./DEPLOYMENT.md)):

- **Slack agents** — set `GATEWAY_SLACK_ENABLED=true` + a Slack bot token/signing secret.
- **GitHub PR review / push** — configure a GitHub App + `GATEWAY_GITHUB_ENABLED=true`.
- **Developer-IDE MCP mount** — `AHS_MONO_ENABLE_MCP=true` exposes `/mcp/platform`.
- **Public exposure** — a Cloudflare tunnel (`deploy/cloudflared/config.yml`).
- **Streamlit login** — a Google OAuth client (`GOOGLE_AUTH_*`).

## Troubleshooting

- **Wizard can't reach Postgres/Redis** — confirm `docker-compose up -d` is
  running and `POSTGRES_CONNECTION_AGENTDB` / `REDIS_URL` match.
- **Smoke test 401/403** — the `X-API-Key` must equal `AGENT_HARNESS_SERVICE_API_KEY`
  from `.env` (generated in Phase 5).
- **Agent turn fails with no output** — ensure a CLI executor (Phase 3) is
  installed and logged in, or that your LLM API key is valid.
- **Deeper options** (Docker one-box, bare-metal systemd, MacBook, secret
  managers) — see [`DEPLOYMENT.md`](./DEPLOYMENT.md) and [`docs/secrets.md`](./docs/secrets.md).
